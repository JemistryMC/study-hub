# Exo Academic Platform

منصة Exo لإدارة المحتوى والدراسة. هذا المستودع هو المصدر المرجعي للكود وسجل المراجعات.

## أين أجد الأشياء؟

- **كود التطبيق والاختبارات:** في جذر المستودع ومجلد `supabase/`.
- **تقارير Gemini ومراجعات ChatGPT:** في [`reports/`](reports/README.md).
- **حالة العمل الحالية:** [`reports/CURRENT.md`](reports/CURRENT.md).

## سياسة الفروع

| الفرع | الاستخدام |
| --- | --- |
| `main` | النسخة المرجعية المستقرة، مع التقارير وسجل المراجعات داخل `reports/`. |
| `Deploying` | تغييرات الكود قيد التنفيذ فقط، بما فيها ملفات الاختبارات والـ migrations المعدّلة. |

لا ترفع تقارير أو ملفات Patch إلى جذر `Deploying`. ملفات الـ Patch التاريخية محفوظة في `reports/patches/`، وهي أرشيف للمراجعة وليست دليلًا على تطبيق التغييرات.

## دورة التعاون

1. Gemini يعمل محليًا ويخرج تقريرًا وملفات معدّلة أو Unified Diff. لا نفترض أن لديه صلاحية رفع مباشرة إلى GitHub.
2. صاحب المشروع يرفع **نص التقرير** إلى `main/reports/phases/<phase>/gemini-report.md`.
3. صاحب المشروع يرفع **ملفات الكود الفعلية** إلى `Deploying` بعملية Commit واضحة.
4. تتم مراجعة الـ Diff والـ CI على SHA محدد قبل اعتماد أي تغيير.
5. لا يتم دمج Pull Request أو نشر Database Migration إلا بعد مراجعة وموافقة صريحة.

## قواعد السلامة

- لا تضع مفاتيح أو كلمات مرور أو ملفات `.env` في GitHub.
- لا تعتبر تقرير Gemini أو نجاح CI وحده موافقة على التغيير.
- يجب ربط كل نتيجة اختبار بـ Commit SHA الذي اختُبر فعلًا.
- لا تطبق migrations على Supabase الفعلية قبل مراجعة مساري Fresh Install وLive Upgrade والتحقق من Staging.
